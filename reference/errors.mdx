---
title: "Error Codes"
description: "Every error code the AssetPay API returns, grouped by category: general, authentication, account access, API keys, trading, wallet, and async trade failures."
---

All errors follow this format:

```json
{
  "requestId": "...",
  "success": false,
  "error": {
    "code": 1001,
    "key": "VALIDATION_FAILED",
    "message": "The request data is invalid"
  }
}
```

Some errors carry extra structured data next to `code`, `key` and `message`:

| Field | Present on | Contents |
|-------|-----------|----------|
| `error.fields` | `VALIDATION_FAILED` (1001) | The validation issues for each rejected request field |
| `error.details` | Selected errors, e.g. `USER_NOT_TRADEABLE` (7), `PRICE_CHANGED` (11), `TRADE_CANCEL_TOO_SOON` (27), `ITEM_OVERSTOCKED` (45) | Error-specific context, documented on the endpoint that returns it |

Codes are grouped by domain:

| Range | Domain |
|-------|--------|
| 1-99 | Trading / marketplace |
| 1000-1099 | Generic / infrastructure |
| 1100-1199 | Authentication / tokens |
| 1200-1299 | Two-factor / passkeys |
| 1300-1399 | Account / access control |
| 1400-1499 | User settings |
| 1500-1599 | Idempotency |
| 1600-1699 | Crypto wallet & funding |
| 1700-1799 | Callbacks / webhooks |
| 1800-1899 | Email |
| 1900-1999 | API keys / secrets |
| 2100-2199 | Risk management |
| 2200-2299 | Booking |
| 2300-2399 | Identity verification |
| 2400-2499 | Ledger integrity |

## General Errors

| Code | Key | HTTP | Description |
|------|-----|------|-------------|
| 1001 | `VALIDATION_FAILED` | 400 | Request body, query or path params failed validation. See `error.fields` |
| 1003 | `NOT_FOUND` | 404 | Resource not found |
| 1005 | `RATE_LIMITED` | 429 | Too many requests |
| 1006 | `SERVER_ERROR` | 500 | Internal server error |
| 1007 | `SYSTEM_MAINTENANCE` | 503 | System is in maintenance mode. Also returned by deposit and withdrawal routes while only those are paused for maintenance |
| 1010 | `NO_BOTS_AVAILABLE` | 503 | No Steam bots are configured or online |
| 1011 | `FLEET_DEGRADED` | 503 | Steam bot fleet is degraded; retry after the `Retry-After` header (30 seconds) |
| 1014 | `DEPOSITS_PAUSED` | 503 | Deposits for this game are temporarily paused |
| 1015 | `WITHDRAWALS_PAUSED` | 503 | Withdrawals for this game are temporarily paused |

Returned by deposit, withdrawal, inventory, and market endpoints.

| Code | Key | HTTP | Description |
|------|-----|------|-------------|
| 1 | `EXTERNAL_ID_EXISTS` | 409 | External ID already exists for this merchant |
| 3 | `INVENTORY_FETCH_FAILED` | 424 | Couldn't load the user's Steam inventory |
| 4 | `NO_OFFER_FOUND` | 400 | No valid offer exists for this item |
| 5 | `TRADE_OFFER_FAILED` | 502 | Failed to send the Steam trade offer |
| 6 | `TOO_MANY_ACTIVE_TRADES` | 429 | User has too many pending trades (per-client deposit guard) |
| 7 | `USER_NOT_TRADEABLE` | 400 | User's Steam account can't trade. On a Steam ban, `error.details` carries `vacBanned`, `gameBans` and `economyBan` |
| 9 | `ITEMS_UNAVAILABLE` | 400 | Selected items not found or no longer available |
| 10 | `ITEMS_NOT_ACCEPTED` | 400 | Items are not accepted for deposit |

| 12 | `MERCHANT_BALANCE_LOW` | 400 | Merchant balance is too low for this withdrawal |
| 13 | `INVALID_TRADEURL` | 400 | Steam rejected a well-formed trade URL. A malformed URL fails with `VALIDATION_FAILED` (1001) |
| 14 | `LISTING_NOT_FOUND` | 404 | Marketplace listing not found |
| 15 | `LISTING_PRICE_INVALID` | 400 | Listing has an invalid or missing price |
| 16 | `INVALID_LISTING_ID` | 400 | Invalid listing ID format |
| 17 | `INSUFFICIENT_ITEM_AMOUNT` | 400 | Requested amount exceeds available quantity |
| 18 | `EXCEEDS_MAX_AMOUNT` | 400 | Requested amount exceeds the maximum allowed |
| 19 | `DEPOSIT_IN_PROGRESS` | 409 | A deposit is already processing for this user |
| 20 | `WITHDRAW_IN_PROGRESS` | 409 | A withdrawal is already processing for this user |
| 21 | `TRADE_NOT_FOUND` | 404 | Trade not found |
| 27 | `TRADE_CANCEL_TOO_SOON` | 422 | Item must be at least 30 minutes old before it can be cancelled. `error.details.cancellableAt` is the unix time (seconds) from which a retry can succeed |
| 28 | `TRADE_NOT_CANCELLABLE` | 409 | Not cancellable in its current state, or the marketplace refused the cancel |
| 29 | `ESCROW_NOT_ALLOWED` | 400 | The trade would be held in Steam escrow; the user must enable the Steam Guard Mobile Authenticator |
| 30 | `INVENTORY_PRIVATE` | 400 | The user's Steam inventory is private or unreachable |
| 31 | `STEAM_UNAVAILABLE` | 424 | Steam temporarily couldn't serve the request; retry shortly |
| 32 | `QUICK_BUY_UNSUPPORTED_GAME` | 400 | Quick buy is not available for this game |

| 44 | `TRADE_CANCEL_UNSUPPORTED` | 409 | The item is Rust or internal-sourced, so there is no supplier cancel to call |
| 45 | `ITEM_OVERSTOCKED` | 409 | We already hold the maximum quantity of one of these items; refresh the inventory and retry. `error.details.items[]` lists `{ itemId, marketHashName, remaining }` |
| 2201 | `ITEM_NOT_FOUND` | 404 | The cancel endpoints found no matching trade, or no matching item under it |

## Asynchronous Trade Failure Codes

The errors above are returned **synchronously** when a call is rejected. A withdrawal that was accepted but later fails carries a separate, smaller, stable code instead: on `Item.error` (and on `Trade.error` when the whole trade failed for one shared cause), typed as [`TradeFailureCode`](/reference/types#tradefailurecode). These are **not** numeric API error codes; they appear on the trade object and in callbacks.

| `error` | Meaning |
|---------|---------|
| `LISTING_UNAVAILABLE` | Listing sold / delisted / out of stock |
| `NO_LISTING_AT_PRICE` | Nothing on sale at or below your max price |
| `PRICE_CHANGED` | Price moved above your ceiling |
| `TRADE_URL_INVALID` | Recipient's Steam trade URL is invalid or escrow-blocked |
| `STEAM_ACCOUNT_RESTRICTED` | Recipient's Steam account can't receive (VAC / ban / hold / private) |
| `BUYER_TRADE_RESTRICTED` | The marketplace suspended this buyer, usually until a stated time |
| `MARKET_UNAVAILABLE` | Temporary upstream / our-side issue. Retry later |
| `PURCHASE_FAILED` | Unclassified failure (catch-all) |

`Trade.error` is typed as [`TradeErrorCode`](/reference/types#tradeerrorcode), on deposits as well as withdrawals. It can hold any value above plus these trade-level outcomes:

| `error` | Meaning |
|---------|---------|
| `USER_TRADE_RESTRICTED` | The user's Steam account can't trade |
| `USER_INVENTORY_PRIVATE` | The user's Steam inventory is private |
| `USER_ESCROW` | Trades with the user would be held in Steam escrow |
| `USER_NOT_FOUND` | No Steam user behind the trade URL |
| `OFFER_NOT_ACCEPTED` | Deposits: the offer reached the user and was not accepted |
| `SERVICE_UNAVAILABLE` | A temporary issue on AssetPay's side. Retry later |
| `MERCHANT_REJECTED` | Withdrawals: your approval callback rejected the trade |
| `APPROVAL_TIMEOUT` | Withdrawals: your approval callback never gave an answer |

`canceled` and `declined` items carry no code: the status is the reason. A `declined` withdrawal is buyer fault: items bought from a marketplace are refunded **minus the penalty** the marketplace kept, and items AssetPay fills from its own stock are refunded in full. See [Withdrawals → Per-Item Failure Reasons](/guides/withdrawals#per-item-failure-reasons) for handling guidance.

## Handling Errors

Check `success` first, then handle based on the error `code` or `key`:

```typescript
const response = await fetch('https://api.assetpay.gg/client/trading/deposit', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': clientToken,
  },
  body: JSON.stringify(depositPayload),
});

const result = await response.json();

if (!result.success) {
  switch (result.error.key) {
    case 'PRICE_CHANGED':
      // Refetch inventory and show updated prices
      break;
    case 'ITEMS_UNAVAILABLE':
      // Remove unavailable items from selection
      break;
    case 'TOO_MANY_ACTIVE_TRADES':
    case 'DEPOSIT_IN_PROGRESS':
      // Tell user to wait for current deposit to finish
      break;
    case 'MERCHANT_BALANCE_LOW':
      // Withdrawal can't proceed, notify user
      break;
    default:
      console.error(`Trade error: ${result.error.key} (${result.error.code})`);
  }
}
```

When contacting support about an error, include the `requestId` from the response. It helps us trace the exact request in our logs.
